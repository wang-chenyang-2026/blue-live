# 排班管理：修复顶部全局统计卡片数值空白

仅在 dev 预览验证，不 deploy，不 push main，不插假数据。请以云端工作区真实代码为准（不要依据任何外部旧副本）。

## 现象
排班管理页（/schedule）顶部 6 个全局统计卡片：覆盖天数 / 排班人次 / 总时长 / 常规时长 / 凌晨班时长 / 双播时长 —— 数值位置空白，只显示单位（天 / 人次 / 小时）。
但下方按日列表正常显示，如「5人次 · 17小时」。
复现条件：日期范围 2026-09-01 ~ 2026-09-27、品牌 vivo、角色 主播、筛选「全部主播」。浅色/深色都可复现。

## 排查重点
1. 读取云端真实的 schedule 页面组件与 /api/schedule 返回结构。
2. 带登录态实际请求一次 /api/schedule（用上述参数），打印 data.globalStats 的真实字段与值。
3. 核对前端渲染顶部卡片时读取的字段名（camel/snake、嵌套层级）是否与接口返回完全一致。
   - 高度怀疑：重构后 globalStats 字段名/位置不一致，导致传入 StatCard 的 value 为 undefined（React 渲染空白），而日级列表 stats 字段一致所以正常。
   - 同时确认「全部主播」分支是否直接采用接口 globalStats（而非本地累加），该对象是否可能为 undefined/字段缺失。
4. 确认 StatCard 对 undefined/null/0 的展示：0 应显示 0（不能空白），仅真正无数据才按设计处理。

## 修复
- 对齐前后端 globalStats 字段映射，保证 6 个卡片数值正确显示；常规时长 = 总时长 - 凌晨班时长。
- 筛选具体主播时，汇总应基于筛选结果正确重算；切回「全部」恢复全局值。
- 数值为 0 时显示 0。

## 自检（必须，实测）
- 带登录态请求接口确认 globalStats 有正确数值；
- 页面：全部主播 与 选定某主播 两种情况下，6 个卡片数值都正确，切换日期/品牌/角色后同步更新；
- 构建通过、无类型错误，不影响其他页面（含百应、/sop）。
