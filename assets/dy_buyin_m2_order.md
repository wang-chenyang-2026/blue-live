# 百应 M2：删除调试区 + 采集任务配置（在 /buyin-spike 上继续）

分支：feat/dy-buyin-spike。仅 dev，不 deploy，不插假数据。复用 M1 已完成的扫码会话（buyin-session.ts 与 start/status/cancel 接口、cookie 已能保存）。

## A. 页面美化：删除底部调试代码
- 移除 /buyin-spike 页面底部「状态与调试信息（结构化）」整块（不再展示 sessionId / startDebug / 原始 JSON）。
- 保留登录成功/失败的友好提示。页面整体保持简洁、沿用 dark/light。

## B. 登录成功后进入「采集任务配置」
在同一页面用步骤区或 Tab 组织：① 连接百应（M1 已有）② 采集任务配置（本次）。未登录时配置区提示先连接。

字段维度数据：使用随单文件 `buyin_fields.json`（81 字段，每项 {field,cn,cat,day,hour,anchor,product}，1=该粒度支持）。请放到合适的项目位置（如 src/lib/data/ 或常量文件）导入使用，不要手填。

### 配置表单字段
1. **任务名称**：文本，便于存模板/识别。
2. **账号/达人**：默认 vivo 官方旗舰店；提供「达人ID by_kol_id」「账号名 by_account」两个输入（可留空走默认）。
3. **数据粒度（多选）**：每日 day / 分时 hour / 商品 product / 主播 anchor。
   - anchor 需排班，选中时给一句说明（按排班窗口汇总，手机订单无法拆）。
4. **指标列勾选**：按 cat 九大类分组展示，每个字段显示中文名 cn + 英文字段 field（次要小字）。
   - 仅展示当前所选粒度"支持"的字段（任一所选粒度对应标志为 1 即可）；随粒度选择动态变化。
   - 每类可全选/清空，整体可"全选"。已选字段按 FIELD 顺序记录，作为该任务输出列。
   - 界面标注数据源固有缺失（hour 无退款/GPM/曝光/停留时长；anchor 无手机订单）——通过支持标志天然不出现即可，不必额外弹错。
5. **商品明细**：开关 with-product-detail（提示请求量翻倍），仅在选了 product 时可用。
6. **数据窗口/回溯**：每次采集回溯天数（如默认 1 天）或起止日期默认值。
7. **获取频率**：下拉 每天 / 每周 / 自定义间隔（天）/ 仅手动。
8. **获取时间**：每天执行时刻（如 10:00；给提示建议早上采前一日，因跨零点归属与 T+ 回调）。
9. **飞书表格交付**：
   - 方式固定为飞书电子表格；
   - 目标：提供「已有飞书表格链接/Token」输入，或勾选「由系统自动新建表格」（M4 交付阶段才真正写入，本阶段先存配置；自动新建时预留回链字段）；
   - 一个 data_type 一个 sheet（开关或默认）；
   - 写入模式：追加 / 覆盖；说明按日期+粒度幂等去重。

### 操作按钮
- 「保存任务」：校验通过后写入数据库；
- 「立即执行一次」：本版可先做成按钮但点击提示"调度执行将在下一阶段启用"（M3 实现），不要假装执行；
- 已保存任务以列表/卡片展示：名称、账号、粒度、频率/时间、交付目标、启用开关、编辑、删除（删除需二次确认）。
- 支持启用/停用、编辑回显。

## C. 数据库
- 新建存储采集任务的表（如 buyin_tasks），字段覆盖上述配置（任务名、kol_id、account、granularities、selected_fields(jsonb/text)、with_product_detail、lookback_days、frequency、interval_days、run_time、delivery_target_type、delivery_feishu_token/url、delivery_auto_create、one_sheet_per_type、write_mode、enabled、创建/更新时间、创建人等）。
- 在 schema 定义并对 dev 库执行建表（drizzle + SQL）；不影响现有表。
- 配套 API：列表、创建、更新、删除（沿用现有鉴权与权限风格）；删除仅删该任务记录。
