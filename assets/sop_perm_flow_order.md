# SOP 在线文档「文档级授权 + 自动重试」工单（v2.16）

## 目标
在线（飞书）文档应用身份读取失败时，平台进入「待授权」，由文档 owner/有管理权限者把**平台应用单独加为该文档的协作者（只读）**，或开启"组织内获得链接可阅读"；授权后系统自动以应用身份重试抓取并展示全文。授权范围仅限单篇，不做按人的大范围 OAuth，不改公司全局权限。

## 关键事实（已核实）
- 飞书有两套机制：①OAuth 按人授权（范围=该用户全部资源，本方案不采用为主）；②文档级协作者授权——可把某个应用/机器人加为单篇文档读者（范围=单篇，本方案采用）。
- 已验证：未授权时 bot 读文档报 131006 / 3380004；wiki 链接需先 get_node 拿 obj_type/obj_token。
- 抓取脚本 codeact/scripts/sop_feishu_content.py 当前用 --as user；需扩展为【优先 bot（应用身份），失败再 user】，以读取"已把应用加为协作者"的文档。
- content_body Markdown 渲染由 v2.15 提供。

## 范围
- 分支 feat/sop-management，dev/预览库；前端状态/按钮 + 服务端飞书权限接口对接；不 push main、不 deploy、不碰生产、飞书仅做必要的单文档协作者添加（由用户显式触发）。

## 任务
1. **读取顺序调整**：在线文档抓取先尝试应用身份（bot）：wiki 先 get_node（bot 若无节点权限则转 user 解析），再 fetch 正文；bot 失败再回退提交人 user 身份。成功写 content_body。
2. **待授权状态**：两种身份都读不了时标记「待授权」，详情页给出明确动作区。
3. **一键把平台加为协作者（单篇）**：
   - 若当前提交人对该文档有管理权限（user 身份），按钮「授权平台读取此文档」调用飞书云文档权限接口，把本应用加为**该文档只读协作者**（仅这一篇）；成功后立即自动 bot 重试抓取并展示。
   - 所需 user scope 取最小（文档权限管理相关 + offline）；操作对象限定该 document_id。
4. **owner 不是提交人**：提供「向 owner 申请文档授权」——可发送/复制一段飞书内请求，引导 owner 二选一：把平台应用加为该文档只读协作者，或开启"组织内获得链接可阅读"；owner 完成后由定时任务/手动「重新检查」自动 bot 读取。owner 无需来平台做 OAuth。
5. **链接分享兜底**：若开启"组织内链接可阅读"后 bot 仍读不到（应用身份不继承链接分享的情况），则提示需"显式把应用加为协作者"，以该方式为准。
6. **安全/审计**：仅单文档授权；记录授权来源与时间；不打印任何 token/secret；不自动扩大到其它文档；链接过滤 javascript:。
7. 兼容 v2.15 正文直出；不破坏 sheet/pdf/image、列表、徽章。

## 验收
1. ts-check / lint（0新增告警）/ build 全绿。
2. 选一篇 bot 读不到的文档：提交人（有管理权限）点「授权平台读取此文档」→ 仅该文档授权 → 自动 bot 重试 → 正文展示。
3. owner 非提交人场景：申请指引正确；owner 加协作者后，「重新检查」/定时能自动读到。
4. 已授权文档不重复授权；user 身份回退链路正常；sheet/pdf/image 回归；dark/light 正常。
5. 测试临时数据/授权按用例还原（如新增的协作者授权在验证后说明是否保留）；完成后自动重启预览返回 preview_url。
