# SOP 图片上传后自动转 PDF 展示（增量需求）

## 背景
紧接「批量多文件上传 + 防误关 + 保存暂存」之后的增量需求。用户希望图片上传后自动生成 PDF，文档页以 PDF 形式展示。本轮在现有文件上传链路（Supabase 私有桶 `sop-files`、`POST /api/sop/documents` multipart、`src/lib/file-extract.ts`、`src/lib/sop-storage.ts`、文档详情页）上增量实现，不推翻批量上传逻辑。

技术栈：Next.js App Router + TypeScript + Tailwind + shadcn；dark/light 双主题；全程中文。

## 功能要求

### 1. 转换范围
- 仅对 **jpg / jpeg / png** 自动转 PDF（可直接无损嵌入）。
- gif / webp / bmp / svg **不强制转换**：保留现有"原图内联展示"行为，不报错。
- 若项目已有或可稳定引入 `sharp`，可先把其它位图格式统一转为 PNG 再入 PDF，从而覆盖更多格式；做不到就严格按上一条，只支持 jpg/jpeg/png，并在文档/提示中如实说明。

### 2. 单图 / 多图规则
- **单张可转图片**：生成 1 个单页 PDF，页面尺寸 = 图片像素尺寸（按 72dpi 换算为 PDF point：1px = 0.75pt），不留多余白边；图片铺满页面。
- **多张图片**：上传弹窗（本地文件模式）提供勾选项「将多张图片合并为一个 PDF（多页）」：
  - **勾选**：本次所有可转图片按列表顺序合并生成 **1 个多页 PDF**，最终只创建 **1 条文档**；文档标题用主标题输入框（多文件合并模式下需显示主标题输入框）。
  - **不勾选（默认行为与批量一致）**：每张可转图片各自生成 1 个单页 PDF、各创建 1 条文档，标题逐项取。
  - 混合文件（图片 + PDF/Word/txt 等）时：合并选项只作用于图片；非图片文档仍各自独立创建，不与图片合并。
- 建议用 `pdf-lib` 在服务端生成（Node 运行时可用）；jpg 用 `embedJpg`，png 用 `embedPng`。

### 3. 存储与数据字段
- 生成的 PDF 上传到同一私有桶 `sop-files`，作为该文档的主文件：`file_kind='pdf'`、`mime_type='application/pdf'`、`file_size`=生成 PDF 的大小、`file_name`=标题或原名去扩展名 + `.pdf`。
- 原图同时保留在桶内（独立 key），新增字段或在现有元数据中记录原图 key（如复用 `file_url` 指向 PDF，另存 `original_file_url` / `original_mime_type`；如不便加列，可用现有备注/元数据字段，但要保证删除时能定位原图对象）。
- 图片 PDF 无文字层：`content_body` 保持为空（**不做 OCR**），因此不触发 AI 自动摘要，属预期行为。
- 走现有签名 URL 机制对外展示，不暴露公开直链。

### 4. 文档详情页展示
- 图片转成的 PDF，详情页"正式内容"区与普通 PDF 一致：内嵌 PDF 预览 + 现有 PDF 展示样式。
- 顶部保留唯一主入口「下载 PDF / 原文件」（下载得到的是 PDF）；另提供次级「查看原图」入口可打开原图。
- 多页合并 PDF 可翻页浏览。

### 5. 删除联动
- 删除文档时，生成的 PDF 对象与保留的原图对象都要从存储桶移除，不得留孤儿对象（复用并扩展现有 DELETE 的清对象逻辑）。

## 约束
- 不影响已完成的：批量多文件追加、弹窗防误关（遮罩/Esc 不关闭、右上角 X、关闭二次确认）、保存暂存（localStorage 草稿）、两栏列表、在线链接模式、权限（仅 PM/运营）、类型/大小校验。
- 仅 `feat/sop-management`；不 push main、不 deploy、不碰生产；不插示例数据；密钥不入码/日志/回复。
- `sop_auto_summary.py` 无需改动（图片 PDF 无文字层，不进入摘要选取）。

## 验收标准
1. 上传 1 张 jpg：详情页内嵌 1 个单页 PDF，页面贴合图片尺寸无明显白边，可下载到正确的 PDF，且可「查看原图」。
2. png 同样可转；上传 gif/webp/bmp/svg 时保留原图内联、不报错、不生成 PDF。
3. 多图勾选「合并为一个 PDF」：只生成 1 个多页 PDF、只新增 1 条文档，页序与图片顺序一致。
4. 多图不勾选：每张图各生成 1 个 PDF、各新增 1 条文档。
5. 图片与 PDF/Word/txt 混合上传：仅图片按合并规则处理，其它文件各自独立，无错乱。
6. 图片转换后的文档 `content_body` 为空、无 AI 摘要（符合不 OCR 预期）。
7. 删除文档后，桶内 PDF 与原图对象都被清除，无孤儿；批量删除同样干净。
8. 批量上传/防误关/保存暂存等既有功能无回归。
9. TypeScript 类型检查、生产构建、相关文件 lint 通过；dark/light 双主题正常。
