# SOP 上传弹窗优化：批量多文件 + 防误关 + 保存暂存

## 背景
SOP「上传内容」弹窗（UploadModal，主要在 `src/app/sop/page.tsx` 内；如已抽成独立组件以实际为准）当前一次只能保留一个文件、点遮罩会误关闭并清空、没有保存中间记录的能力。本轮只改这个上传弹窗及其必要的前端逻辑，后端接口尽量复用。

技术栈：Next.js App Router + TypeScript + Tailwind + shadcn。需同时兼容 dark/light 双主题，全程中文，风格与全站一致。

## 需求一：支持批量多文件（核心）

1. 文件选择框 `<input type="file">` 加 `multiple`；拖拽区（drag & drop）支持一次拖入多个文件。
2. 内部用"文件数组"管理。新选择或新拖入的文件一律**追加**到列表，**绝不允许新文件替换/覆盖已有文件**（这是当前的主要 bug）。
3. 仍走现有白名单与大小校验（文档 pdf/doc/docx/ppt/pptx/txt/md 单文件 ≤30MB；图片 png/jpg/jpeg/gif/webp/bmp/svg ≤10MB）。追加时对每个文件单独校验：不合法的文件给出明确提示（类型不符/超限），不入列表，但不影响其它合法文件。
4. 文件区改为**文件列表**展示：
   - 图片显示缩略图；非图片显示对应类型图标。
   - 每项显示：文件名、大小、（可编辑的）标题、单个"移除"按钮。
   - 提供"继续添加"入口，可多次追加。
   - 重复文件去重：按 `name + size + lastModified` 判断，重复的提示并忽略。
   - 单次最多 20 个文件，达到上限提示。
5. 标题处理：
   - **单文件**：保持现在的主"标题"输入框，默认值=文件名去掉扩展名，用户可改。
   - **多文件**：隐藏/替换顶部单一标题输入框为一句说明（如"将分别创建 N 条文档，标题可在下方逐个修改"）；在每个文件项内放一个小标题输入框，默认=该文件名去掉扩展名，可逐个修改、可为空时回退为文件名。
6. 业务线（一级）、分类（二级）、"该文档后续需要考核"、备注 作为**公共字段**，批量套用到本次所有文件。
7. 提交（"确认上传"）：
   - 复用现有 `POST /api/sop/documents`（multipart），对文件数组逐个提交（可有限并发，建议 2~3 个，避免打爆），**不新增后端批量接口**；如复用确有困难再议，优先复用。
   - 显示整体进度（已完成 n/总数）与每项状态（等待/上传中/成功/失败）。
   - 单个文件失败只标记该项失败、可"重试失败项"，**不得中断**其余文件。
   - 全部成功后：成功提示、关闭弹窗、清空草稿、刷新 SOP 列表（应出现对应条数的新记录，分类等公共字段一致）。
   - 存在失败项时保留弹窗，失败项标红，可重试；已成功的不重复提交。

## 需求二：弹窗只能主动关闭

1. 点击遮罩（overlay/弹窗外空白区域）**不关闭**；按 `Esc` **不关闭**。若用 shadcn Dialog，通过 `onPointerDownOutside`、`onInteractOutside`、`onEscapeKeyDown` 阻止默认关闭行为。
2. 弹窗**右上角新增明显的关闭"X"按钮**；底部现有"取消"按钮保留。X 与"取消"都属于"主动关闭"。
3. 关闭前判断是否有内容（已选文件，或标题/备注等相对初始状态有改动）：
   - 有内容：弹二次确认（不要用 window.confirm，用与全站一致的确认弹窗），文案如"还有未上传的内容，确定关闭吗？可先点『保存』保留进度。"，提供"继续编辑 / 仍要关闭"。
   - 无内容：直接关闭。
4. 关闭后：若已保存草稿则保留草稿（见需求三）；未保存则按确认结果清空本次状态。

## 需求三：增加"保存"按钮（暂存本次上传记录）

1. 底部按钮区调整为：`取消` ｜ `保存`（次要样式）｜ `确认上传`（主要样式）。
2. "保存"把当前弹窗状态持久化到浏览器 `localStorage`（独立 key，如 `blue_sop_upload_draft`），包括：
   - 上传模式（在线链接 / 本地文件）
   - 所有表单字段：标题（或多文件的逐项标题）、一级业务线、二级分类、是否考核、备注
   - 已选文件的元数据清单（name/size/type/lastModified）
3. 文件对象（File/Blob）在**不刷新页面**时保留在内存中：关闭弹窗后再次打开（同一页面会话），文件列表、缩略图、所有填写内容**完整恢复**，可直接继续上传。
4. 重新打开弹窗时若检测到草稿：
   - 同一会话（文件句柄仍在）：完整恢复，顶部显示提示条"已恢复上次未完成的上传（N 个文件）"，并提供"放弃草稿"。
   - 若页面已刷新：受浏览器安全限制，File 对象无法持久化。此时恢复全部文字字段与文件清单，但在对应文件项标注"需重新选择"，并提供重新选择入口；在文件补齐前，"确认上传"置灰禁用。
5. "保存"点击后给轻提示（如 toast"已保存，可随时继续"），**不关闭弹窗**。
6. 草稿清理：
   - "确认上传"全部成功后自动清除草稿。
   - "放弃草稿"手动清除（仅清本机草稿与内存状态；本方案文件未提前上传到存储桶，无孤儿对象）。
7. 在线链接模式同样适用该暂存逻辑（保存链接与表单字段）。

> 说明（交付时也要如实告知用户）：本轮"保存"为**本机浏览器暂存**，用于防误关、防误刷新丢内容；同页面会话内文件可完整恢复，刷新页面后因浏览器限制文件需重新选择（文字不丢）。如后续需要"保存为跨设备/跨天、文件也不丢的正式草稿"，再升级为"暂存到私有存储桶/草稿落库"方案。

## 约束（务必遵守）
- 只改 SOP 上传弹窗相关前端代码及必要的状态管理；后端现有单文件 POST、权限（仅 PM/运营可上传）、类型/大小校验、Supabase 私有桶 + 签名 URL、DELETE 联动清对象等逻辑保持不变。
- 不新增示例数据；不改 AI 自动摘要（本轮草稿不落库，`sop_auto_summary.py` 无需改动）；不影响 SOP 两栏列表、文档详情页现有功能。
- 仅在 `feat/sop-management` 分支；不 push main、不 deploy、不碰生产库。
- 令牌/密钥不得写入代码、日志或回复。

## 验收标准
1. 一次选 3 张图片，文件列表出现 3 项；再选第 4 个变成 4 项，已有文件不被替换。
2. 一次拖入多个文件能正确追加；可单独移除任意一项；重复添加同一文件被去重。
3. 多文件"确认上传"后，SOP 列表新增对应条数记录，逐项标题正确，业务线/分类/考核/备注一致。
4. 单文件上传的标题与流程和原来一致，无回归。
5. 上传中有单个失败时，其余照常成功，失败项可单独重试且不重复提交已成功项。
6. 点击遮罩空白、按 Esc，弹窗均不关闭。
7. 右上角有关闭 X；有内容时点 X/取消会二次确认，无内容直接关闭。
8. 点"保存"有成功提示；不刷新页面情况下关闭再打开，文件与全部填写完整恢复；可"放弃草稿"。
9. 刷新页面后重开：文字字段恢复，文件项标注"需重新选择"，未补齐时"确认上传"禁用。
10. 全部上传成功后草稿被自动清除。
11. 非 PM/运营账号仍无法上传（403）；非法类型/超限仍被拦截。
12. TypeScript 类型检查、生产构建、相关文件 lint 均通过；dark/light 双主题显示正常。
